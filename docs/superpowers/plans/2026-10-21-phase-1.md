# Phase 1 Implementation Plan

**Goal:** Lauffähiger, isolierter Multi-Asset-Scanner mit einem realen Spot-Anbieter.
**Architecture:** Lesende FastAPI und separater Worker teilen PostgreSQL. Provider,
Detektor und Persistenz bleiben unabhängig voneinander testbar.
**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy, Alembic, PostgreSQL 17, pytest.
**Spec:** ../specs/2026-10-21-phase-1-design.md
**Execution:** Direkt in dieser Sitzung auf Feature-Branch; Nutzer hat Umsetzung bestätigt.

## Global Constraints
- Kein Live-Trading, keine Schlüssel; eigene Compose-Ressourcen, Dashboard nur lokal.
- Nur abgeschlossene Kerzen; keine zukünftigen Vergleichsdaten.
- PostgreSQL privat; Migration vor API/Worker-Start.

## Review Focus
- Offene, zukünftige oder lückenhafte Kerzen: kein falsches Signal.
- Ungültige HTTP-Antworten/Rate-Limits: begrenzte Wiederholung und sichtbarer Fehler.
- Wiederholter Import: keine doppelten Daten oder Entscheidungen.
- Datenbankausfall: Readiness fehlerhaft, Liveness bleibt verfügbar.
- Parallele Worker: genau ein aktiver Scan pro Datenbank.

## Tasks
1. Domain und Anbieter (`scanner/domain.py`, `providers/`, `detector.py`):
   Tests zuerst für Candle-Validierung, abgeschlossene Binance-Kerzen, Retry,
   Fixture-Replay und Volumenspitzen einschließlich Lücken/Nullvolumen. Danach
   implementieren, pytest ausführen und committen.
2. Persistenz und Worker (`models.py`, `service.py`, `worker.py`, `migrations/`):
   Tests zuerst für idempotenten Import, Audit-Trail und Fehlerisolation.
   SQLAlchemy-Schema und Alembic-Migration implementieren, SQLite-Tests und echten
   PostgreSQL-Migrations-/Lock-Test ausführen, committen.
3. API und Betrieb (`main.py`, `templates/`, Compose, Dockerfile, README):
   Tests zuerst für lesende Endpunkte, Pagination und Readiness. Dashboard,
   Konfigurationsvalidierung und isolierte Compose-Services implementieren.
   Gesamtsuite, Ruff, Compose-Konfiguration und Container-Smoke-Test ausführen.
4. Änderungen prüfen, Testergebnisse dokumentieren, Feature-Branch pushen und
   Pull Request mit Ergebnissen und klaren Phase-1-Grenzen erstellen.
