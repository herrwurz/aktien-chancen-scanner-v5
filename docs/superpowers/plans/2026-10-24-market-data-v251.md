# Scanner V6 V2.5.1 Historical Market Data Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build a provider-neutral, revision-preserving US EOD price pipeline linked to the SEC universe and exposed through `research.prices`.

**Architecture:** Reuse the immutable Tiingo/EODHD raw collectors. Normalize provider responses into one strict contract, append idempotent revisions to a local SQLite research artifact, and query it in strict or explicitly modeled historical-availability mode. A bounded pilot CLI deterministically selects ten SEC issuers before price retrieval and emits an auditable coverage report.

**Tech Stack:** Python 3.12, Pydantic, SQLite, httpx, pytest, Ruff, Docker.

**Spec:** `docs/superpowers/specs/2026-10-24-short-term-stock-scanner-v25-design.md`

## Global Constraints

- No paid booking, deployment, merge, productive database migration, trading, or Immich access.
- Provider network access requires explicit flags, credentials, request ceilings, and cost declaration.
- Synthetic fixtures prove only normalization and failure handling; real coverage is reported only from archived provider responses.
- Raw and adjusted prices, observed retrieval and modeled market availability remain separate.

## Review Focus

- Corrected provider rows must append revisions without overwriting prior observations.
- Ticker/exchange/MIC mismatches must block import rather than silently relink an SEC identity.
- Strict historical queries must not expose data retrieved after `as_of`.
- Modeled availability must be visibly hypothetical and training-ineligible.
- Missing official calendars or quotes must remain unavailable rather than inferred from weekdays/OHLCV.
